# REVIEW.md

Starter `app/main.py` reviewed as a pull request. All items below are fixed in the submitted file.

| # | Where | What is wrong | How you'd notice it | How I fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Floors to whole minutes **before** the `> 10` check, so the grace test is on a rounded value. | Shift 09:30, punch 09:40:01 -> returns 0, R2 says 10. | `delta` in seconds: late only if `delta > 600`, then `delta // 60`. |
| 2 | `compute_late_minutes` | `punch_in.replace(hour=..)` uses the datetime's own date/zone (UTC or server-local), not the IST attendance date. Overnight shifts also start the previous day. | IST 00:10 punch on a 09:30 shift is compared with the wrong day; overnight punch 21:55 gets a wrong start. | `ist_instant(attendance_date, shift_start)` with the R1 date. |
| 3 | `compute_work_hours` | Built-in `round()` on a float: banker's rounding plus binary noise. No half-day logic (R5). | 54 s -> 0.015 h -> `round` gives 0.01, half-up gives 0.02 (554 such values below 40 000 s). | `Decimal` division, `quantize(0.01, ROUND_HALF_UP)`; `half_day` from the rounded value `< 4.50`. |
| 4 | `compute_overtime` | No 30-minute minimum (R3); overnight shift end is computed on the same day, so it is hugely negative and becomes 0; `fromisoformat(date_str).replace(tzinfo=IST)` breaks with naive punch_out (TypeError). | 18:40 punch-out shows 10 min overtime; overnight 06:40 shows 0. | `shift_end` on the next day for overnight, `minutes >= 30` else 0, all datetimes aware. |
| 5 | Whole file (time handling) | `datetime.now()` / `fromtimestamp()` use the server's local zone; MongoClient returns **naive** datetimes; aware minus naive raises. | Different results on a UTC vs IST host; 500 when a stored datetime meets an aware one. | `MongoClient(tz_aware=True)`, every instant is aware UTC, converted to/from epoch ms only at the boundary (`ms_to_dt`, `dt_to_ms`). |
| 6 | `punch_in` | Date taken with `ts.date()` (server zone), no R1 overnight rule. | IST 00:10 punch is filed under the previous UTC day; overnight 03:00 punch gets its own new day. | `attendance_date()` implements R1. |
| 7 | `punch_in` | Unknown employee: `emp` is `None`, `emp["shift_start"]` raises -> 500. | POST with an unknown `emp_code`. | `get_employee_or_404`. |
| 8 | `punch_in` | Check-then-insert race and no unique index; two parallel requests both pass the `find_one`. | 10 parallel identical requests -> several 201 and duplicate documents. | Unique `(emp_code, date)` index created at startup; `insert_one` and map `DuplicateKeyError` to 409. |
| 9 | `punch_in` / `PunchInIn` | `status` is any string (accepts ABSENT, LEAVE, garbage). `punched_at: 0` is treated as "now" (`if body.punched_at`); seconds-looking, float and out-of-range values accepted; sub-seconds not truncated (R1). | `{"status":"ABSENT"}` returns 201; `punched_at: 1783312500` creates a 1970 record. | `Literal["PRESENT","WFH","ON_DUTY"]`, `StrictInt` bounded to the ms range, `is not None` check, truncation to whole seconds. |
| 10 | `punch_in` response | Leaks `id` (ObjectId as string), returns datetimes instead of epoch ms. | Response has `id` and ISO strings. | `record_out()`: no `_id`, epoch ms, defaults for legacy fields. |
| 11 | `create_employee` | Check-then-insert race, no unique index, no input validation (emp_code format, email, `HH:MM`, `shift_start == shift_end`, `joined_on`). Naive `created_at`, returned as a datetime not ms. | Parallel creates -> duplicates; `shift_start: "9:3"` accepted. | Unique index + `DuplicateKeyError` -> 409; Pydantic patterns/validators -> 422; server `created_at` as ms. |
| 12 | `list_employees` | `skip = page * page_size` skips the first page; `total` counts the whole collection, not the filter; no sort; page/page_size unbounded (page 0 -> negative skip -> 500). | `page=1` returns the 2nd page; `total` ignores `department`. | `(page - 1) * page_size`, `count_documents(filter)`, sort by `emp_code`, `ge=1`, `le=100`. |
| 13 | `list_attendance` | Loads **every** matching document, sorts and slices in Python; sort has no `emp_code` tiebreak; no indexes; unbounded page_size; unvalidated dates/status; `date_from > date_to` not rejected; returns `id` and raw datetimes; legacy documents lack `history`/`half_day`. | Seconds per call and memory growth at 100k docs; unstable order within a date. | Database-side `find().sort().skip().limit()` with `count_documents`, compound indexes, validated filters (422), `record_out()` with defaults. |
| 14 | `/health` | Always returns ok, even if MongoDB is down. | Stop MongoDB and call `/health`. | Pings MongoDB, else 503. |
| 15 | Startup | No indexes are created. | `explain` shows COLLSCAN. | `ensure_indexes()` in the lifespan hook, idempotent, retried from `/health` if MongoDB was not up yet. |
| 16 | Error handling | Driver errors surface as 500. | Kill MongoDB during a request. | `PyMongoError` handler returns 503. |

**Examined and judged fine:** `load_dotenv()` before reading env (default `override=False`, so real environment variables win, as required); the `IST` constant (+05:30 is correct); `doc.pop("_id")` after `insert_one` (works, though it mutated the response); `HTTPException(409)` for duplicates (right status, wrong mechanism, see 8 and 11). The starter's helper signatures could not be reused as they are: they all take or assume naive datetimes, so I replaced them with `calc_late_minutes`, `calc_overtime_minutes`, `calc_work_hours` and `derive`.
